# WS2812 灯带：把陪伴延伸到工位环境

屏幕负责细节，灯带负责余光就能感受到的轻量反馈。XIAO 固件提供白色补光、慢呼吸、流动和彩虹四种模式；命令行、HTTP、本地 MCP 和 BLE 使用同一套模式名称。关闭补光后，可用低亮状态灯显示主控与 Indicator 的连接情况。四线 WS2813 类灯带可使用项目的可选 RMT 驱动；接线与配置见下文。

灯光是桌面氛围，不是植物健康读数，也不是经过光合标定的生长灯。网页灯珠环和粒子是可交互预览，不连接真实灯带；网页展示的灯珠数量不能当作实际配置。

当前台架使用 Grove WS2813 四线灯带，RGB GPIO40，已扩展为 30 颗，亮度上限保留 24/255；使用 RMT 驱动路径。2026-11-03 用户确认 Indicator 操作下 30 颗绿→白→绿正常，屏幕触摸正常。本教程的 WS2812 名称指兼容单线协议家族，不代表所有 Grove 灯带可直接互换。手机语音开关灯仍需单独验收。

固件哈希、配置保留核对和现场结果见 [2026-11-03 灯带更新记录](../deployment/status-strip-20261103.md)。

## 在线状态与白光补光

- **低亮绿色**：主控网络已连接，且收到 Indicator 的土壤数据上传；最近一次有效上传的估计数据年龄不超过 10 秒。手机和打印机按需连接，不参与这个在线判断。
- **低亮琥珀色**：主控未联网，或暂未收到 Indicator 的新上传。它表示连接待恢复，不代表植物缺水。
- **白色补光**：Indicator 点“开启补光”，或通过 YOYO、HTTP 开灯时，默认 30 颗显示白光。已启用的环境光自动模式也使用白光。
- **关闭补光**：回到当时的绿色／琥珀色状态。补光和主动选择的动画优先于状态色；断连不会把正在运行的白光强制改成琥珀色。

状态灯需配置 `ROBO_ENABLE_STATUS_LIGHT 1`，并启用灯带、设备动作和 Indicator 数据上传。默认通用配置不启用它。关闭该选项时，关灯仍为全部熄灭。状态判定的 10 秒容忍窗口不改变传感器读数自身的 3 秒有效期；上传中的传输延迟计入数据年龄。状态灯不会修改自动补光设置或触发手动优先。

## 1. 四种模式怎么选

| 模式 | 命令值 | 固件行为 | 适合的使用时刻 |
| --- | --- | --- | --- |
| 白色补光 | `solid` | RGB(255,255,255)，再应用亮度上限；未传模式时使用它 | 手动或自动补光 |
| 慢呼吸 | `breath` | 4 秒一个明暗周期，端点平滑过渡 | “今天省电生长”的工位氛围 |
| 流动 | `chase` | 绿色光点每 240 ms 前进一颗，带低亮尾迹；仅一颗灯时改为呼吸 | 展示灯带走向和空间感 |
| 低亮彩虹 | `rainbow` | 12 秒一个颜色周期，颜色沿灯带分布 | 短时展示、社媒近景 |

所有模式叠加 `ROBO_LED_BRIGHTNESS` 的编译期亮度限制；没有远程自由调色、速度或亮度接口。上电补光默认关闭，不保存上次灯效；启用状态灯时，初始化完成后先显示等待连接的琥珀色，再按实际连接显示绿色。若此前保存了自动模式，收到稳定环境光采样后会重新判断开关。手动开灯未指定模式时使用白光。Wi-Fi/BLE 断连不会直接关闭补光，主控继续执行本地灯光逻辑。

默认应该安静，动态效果由用户选择。连接状态提示已实现；专注完成庆祝、YOYO 自然语言选择动画和植物状态联动尚未自动触发。不要把“情绪不好”变成强制灯光，也不要用拒绝互动来惩罚用户。

## 环境光自动开关：在 Indicator 设置阈值

入口：**设置 → 灯光设置**。页面显示实时环境光ADC和灯带状态，可以切换自动模式，并分别设置“低于或等于此值开灯”和“高于或等于此值关灯”。加减每次调整100，也可点数值区域采当前值。调整后点“保存灯光设置”，看到保存提示才生效；退出不保存会丢弃草稿。

- ADC范围0–4095，越大越亮；不是lux。默认自动关闭，开灯阈值1200、关灯阈值1800只是起始值，应按实际工位采集。
- 关灯阈值须比开灯阈值至少大64。处于两阈值之间保持原状态；满足连续三次新采样、持续至少两秒后才切换，减少临界点闪烁。
- 设置保存在XIAO的NVS，断电重启保留；自动判断在XIAO运行，Indicator不在线也能工作。自动开灯使用白色补光，自动关灯回到连接状态灯（若启用）。
- Indicator或YOYO手动开关灯后，自动模式暂停，尊重手动选择。页面显示“手动优先中”，点“保存并恢复自动”恢复；主控重启也会恢复已保存的自动模式。若希望重启后也保持手动控制，请关闭自动模式并保存。
- 关闭自动模式不会额外发送关灯命令，灯带保持当前状态，可继续手动开关。自动模式运行时环境光无效或超过三秒未更新会关灯；手动优先期间不套用这条自动规则。

浇水运行时不能保存灯光设置；保存期间暂不接受新浇水或手动灯光命令。断网或保存结果未知时先等状态读回，不自动重发。接口见[设备协议](../device-protocol.md)。

## 2. 断电接线与供电检查

先完成 [硬件总教程](hardware-quickstart.md) 的板型识别、原程序备份和供电检查，按自己实物的丝印核对连接器方向：

1. 灯带必须兼容 **GRB、800 kHz** 单线协议；确认其额定电压。不能只凭“RGB 灯带”商品名判断兼容性。
2. 灯带 **DIN → Robot Board V1.0 的 J7 pin1**，信号来自 GPIO40，经板载缓冲输出。不要接到灯带 DOUT。
3. 灯带 **GND → J7 pin4 / 公共地**。确认灯带额定 5 V、电源及连接器容量足够，才考虑使用 J7 pin3 的 VSYS_5V。
4. 按真实型号、灯数和最坏情况功耗做电流预算；长灯带需要按电气要求独立供电、补电及保护，独立电源仍要共地。不能只靠降低软件亮度弥补供电不合格。
5. 从少量灯珠、较低亮度开始，不连接未经确认的水泵或打印负载。

这里的 pin1 是原理图编号，不是从任意视角看的“最左一脚”。转接线顺序不确定时用万用表核对，不凭线色猜测。

## 3. 配置、构建和手动烧录

复制 `firmware/xiao/include/config.local.example.h` 为同目录的 `config.local.h`，只在这份本地配置文件中修改配置。替换默认令牌，并让客户端使用同一个令牌；不要把真实令牌写进公开文件、Skill 或截图。

下面是本地配置项说明，灯数必须改为你实际连接的数量：

```cpp
#define ROBO_ENABLE_ACTIONS 1
#define ROBO_ENABLE_LIGHT 1
#define ROBO_LED_COUNT 30      // 当前台架；按实际数量修改，允许 1–120
#define ROBO_LED_BRIGHTNESS 24 // 0–255，先低亮度验证
#define ROBO_ENABLE_STATUS_LIGHT 1 // 需 Indicator 持续上传数据
#define ROBO_ENABLE_PUMP 0
#define ROBO_ENABLE_PRINTER 0
```

完整配置请从示例文件复制。项目默认文件仍关闭所有外设。按 [构建和烧录步骤](hardware-quickstart.md) 编译 XIAO 工程，确认目标和配置后由你手动烧录；更新灯数或亮度后须重新构建并烧录。

## 4. 先验证常亮与关灯，再逐项试效果

电脑连接 XIAO 的热点，并按硬件教程设置 `ROBOPLANTER_TOKEN`。以下命令发送真实设备动作，每条新命令生成自己的请求 ID：

```bash
python3 tools/device_cli.py state
python3 tools/device_cli.py light on
python3 tools/device_cli.py light off
python3 tools/device_cli.py light on --effect breath
python3 tools/device_cli.py light on --effect chase
python3 tools/device_cli.py light on --effect rainbow
python3 tools/device_cli.py light off
```

Windows 将 `python3` 换成硬件教程中的 `& $rpPython`；Linux 若使用虚拟环境，换成 `"$rp_python"`。等当前命令回包并观察实物，再发送下一条；不是整段粘贴后声称验收完成。`light off --effect ...` 会在客户端直接拒绝。

状态中应看到 `light.enabled:true`、对应的 `light.on` 和 `light.effect`。`on` 只表示补光／主动灯效是否开启，状态灯亮着时它仍可为 `false`。关灯时 `effect` 归一为 `solid`。`display_mode` 区分 `fill`、`effect`、`status_online`、`status_waiting` 和 `off`；`pixel_count`、`brightness_limit`、`status_enabled` 可核对实际固件配置。旧固件缺少这些字段时先升级，不自动回退成其他效果。

`completed` 表示软件已完成设置，不是光学传感器确认灯亮；没有亮、颜色不对、闪烁或复位时立即关灯/断电，按 [排障手册](troubleshooting.md) 检查。

## 5. HTTP、BLE 和 MCP 的同一契约

HTTP 继续使用 `/api/v1/command` 及 `X-Device-Token` 请求头。例如：

```json
{"request_id":"lamp-01","action":"light","on":true,"effect":"breath"}
```

`effect` 仅在 `on:true` 时可选，严格接受 `solid`、`breath`、`chase`、`rainbow`。省略等价于 `solid`；关灯不带此字段。没有组合动作或额外参数。省略与显式 `solid` 是相同幂等请求；相同 ID 换模式会冲突，不能用新 ID 自动补发一个结果未知的动作。

当前绑定BLE v2使用公开V前缀（非令牌）；以下例子以新请求ID替换id：

```text
V|C|id|light|1          白色补光
V|C|id|light|1|breath   慢呼吸
V|C|id|light|1|chase    流动
V|C|id|light|1|rainbow  彩虹
V|C|id|light|0          关闭补光，恢复状态灯（若启用）
V|S|light              回包仍为 L:enabled:on
```

`V`是公开版本标记，`id`是请求编号，不是真实凭据；BLE 的 ID 最多 8 字符，请求总长最多 240 字节。查询格式维持兼容，**BLE 查询不回报模式**；需要模式读回时使用 HTTP `light.effect` 和 `light.display_mode`。荣耀的长写、通知和加密配对条件见 [BLE 教程](ble-integration.md)。当前工位小芽 Skill 提供开关灯；手机验收仍需单独记录，四种效果的语音选择未在 Skill 中映射。

本地 MCP 的六工具数量不变，`set_light(request_id, on, effect)` 增加可省略的枚举参数。云端 MCP 的所有写操作仍禁用，不能通过本地灯效参数绕过。

## 6. 动画与验收

帧生成在独立低优先级任务中运行，按时间计算动画；发送开关命令不需要等待整个呼吸或彩虹周期结束。灯带输出锁与控制器锁分开，NeoPixel 输出时不占用泵控制器锁。关闭补光会直接切换到当前状态色（未启用状态灯时清空灯带），不排在完整动画后面；实际延迟仍需实体板测量。静态颜色只在状态变化时更新，不重复发送相同帧。

软件测试覆盖模式解析、非法参数、默认模式兼容、同 ID 去重与冲突、各帧颜色上限、单灯退化、关灯、计时回绕，以及 30 颗状态色、白光优先和关闭补光恢复状态。实机还要逐项记录：

- 灯数、颜色顺序、接线照片、固件版本、低亮度下的四种效果视频。
- 动态效果中关闭补光，确认回到状态色；禁用状态灯时应熄灭。重新开机先关闭补光，再按已保存的自动模式判断。
- 断连与重连后实际状态符合本页说明，不冒充收到命令。
- 在已有安全台架条件下验证动画运行时 HTTP/BLE 响应与泵截止时间；不要为测试灯光临时启用未验收水泵。
- 电源、连接器和灯带无异常发热，长时间运行没有复位。

## 7. 一个能拍出记忆点的镜头

人物说“今天电量只剩一点点”，镜头从屏幕小精灵移到桌沿慢呼吸，字幕接“那我们今天省电生长”。切一个流动模式近景，再回到人继续做自己的事。最后一句可以是：“它不催我上进，主要催自己发芽。”

网页录屏标“灯效预览”，完成实体板验证后的实拍才标“WS2812 实机灯效”。保留环境光下的真实亮度，不用后期光圈冒充硬件，也不把彩虹变化叫作植物健康监测。

当前 YOYO 工位小芽使用加密绑定的 `V|C|id|light|1` / `0`；旧版 token 格式不能直接放入当前 Skill。四种灯效的固件能力不等于 Skill 已开放全部灯效话术。见[BLE v2](ble-integration.md)。

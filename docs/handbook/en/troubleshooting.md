# Recover the failed link, not the whole project

## A greeting cannot open the Skill

Check the correct private entry and its platform publication/installation state. The older entry once remained unavailable even after republication; the replacement entry restored ordinary chat. Bluetooth re-pairing cannot fix a Skill that fails before calling a hardware tool.

## Chat works, hardware requests fail

The phone connects to **XIAO** over BLE. On the Indicator, inspect the YOYO/connection page and try Reconnect phone (keep binding). A bound phone does not need another code for each request. Only use explicit re-binding for a real ownership/bond-repair need; obtain a fresh code from the screen.

## Indicator is offline

Check the 2.4 GHz network, controller discovery/address, device identity and HTTP authorization. A Wi-Fi icon alone proves none of the latter. A phone Bluetooth reset does not repair a screen HTTP-token mismatch. Settings persist in flash; follow the shared network-setup stages and inspect the actual error.

## Soil appears as a large integer

Use the current calibrated `soil` query and the latest compatible firmware contract. Raw ADC is diagnostic only. Missing calibration needs actual dry/wet reference capture, not a guessed formula in the language model. Compare the phone and screen within the normal sampling delay.

## No ultrasonic reading

Power down before reseating or changing wires. Confirm SIG is on **J10 RX/D7/GPIO44**, with independent 3.3 V and common ground, and no printer TX wire. Use a dry sensor and a flat target 10–20 cm away. A multimeter can check supply and idle signal levels, but cannot replace an echo timing measurement. Recheck the tank after remounting. Keep normal watering disabled while water data is invalid.

## Printing stalls or is flattened

Isolate printer power and FEED/self-test first, then the current BLE connection. Re-enable Bluetooth after a printer power cycle and disconnect other clients. Query the original action result before retrying. Use the tested 128-row raster path; do not treat an old UART diagram as current wiring. See [printer guide](uart-printer.md).

## Display flashes or reboots

Check reset/crash logs and the correct panel configuration before attributing every flash to animation. A previous reboot issue was fixed independently of the older refresh/double-buffer issue. Use the stable build and preserve settings; do not change multiple display parameters and wiring at once.
